# 352 Air Legacy Local

[English](README_EN.md)

为已经联网的老款 352 空气设备提供完全本地的 Home Assistant 接入。集成
通过局域网 UDP 11530 读取状态和发送控制，不需要 352 账号，也不会连接
已经失效的旧云服务。

> 本项目是社区维护的非官方集成，与 352 厂商没有隶属或背书关系。

## 为什么有这个项目

2019 年前后的 352Air App 目前已经难以正常登录，但 X83C 等设备本身仍
会在局域网广播状态，也接受本地控制。项目通过 APK 静态分析、脱敏抓包
和 X83C 真机验证重新记录了这些本地协议，并按 Home Assistant 2026.8
接口从零实现。

感谢 [yymonday/ha-352-airpurifier](https://github.com/yymonday/ha-352-airpurifier)
保存了早期 X83/X50 接入经验。当前 v3 是新的 GPL-3.0-or-later 实现，
不继承旧项目源码和 Git 历史。技术证据与已知边界见
[协议分析](docs/protocol-analysis.md)，完整的旧 App 拆包结论见
[APK 静态分析报告](docs/apk-static-analysis.md)。

## 支持程度

| 型号 | 状态读取 | 控制 | 证据与说明 |
|---|---|---|---|
| X83C | 支持 | 支持 | 本项目 2019 款真机验证；鉴权码从设备学习 |
| X83 | 支持 | 支持 | 原项目实机报告可用；v3 使用同一 A5A0 协议族 |
| X50 | 支持 | 实验性 | 原项目列为实机可用；不同固件的本地控制存在差异 |
| X83C Plus | 实验性 | 实验性 | APK 确认属于 X83 协议族，无对应真机 |
| X50S / X60 / X70 | 实验性 | 实验性 | APK 确认共用 X50 协议族，无对应真机 |
| G30 / G45 | 实验性 | 实验性 | APK 确认长帧、CRC 和控制表，无对应真机 |
| M25 | 实验性 | 仅背光 | M25 是检测仪，不提供净化器电源/模式/风量控制 |

“APK 确认”只表示旧 App 中存在对应构造器和解析器，不保证所有硬件或
固件接受控制。欢迎有设备的用户反馈脱敏结果。

## 主要功能

- 局域网自动发现和手动 IP/MAC 配置。
- 从设备响应学习 company、协议族和鉴权码，不跨型号写死。
- 主风扇实体：0% 关机、非零风量、自动/手动和风量滑块。
- HA 模式选择：自动、睡眠、极速及型号支持的实验性极净模式。
- PM2.5、空气质量、本次开机处理空气量、寿命累计净化空气量、定时剩余
  及各型号已确认的环境传感器。
- 童锁、屏幕、关机定时，以及 G30/G45 的 PTC 控制。
- 被动接收设备广播，并在广播中断时使用只读查询恢复状态。
- 简体中文界面；其他 HA 语言自动使用英语。
- 全部设备通信保持在本地网络。

X83C 的手动模式由风量命令进入。真机对模式命令值 4 和 5 均无响应，
因此本项目不会把“极净”伪装成已支持的 X83C 模式；“极速”是另一个可
持续运行的模式。

## 通过 HACS 安装

当前作为自定义仓库安装：

1. 在 HACS 打开“集成”。
2. 右上角菜单选择“自定义存储库”。
3. 添加：

   ```text
   https://github.com/jack16683/ha-352air-legacy-local
   ```

4. 类别选择“集成”，下载 **352 Air Legacy Local**。
5. 重启 Home Assistant。
6. 进入“设置 → 设备与服务 → 添加集成”，搜索
   **352 Air Legacy Local**。

自动发现会先识别协议族；同一协议族包含多个零售型号时会要求确认。
扫描失败时使用手动配置，填写设备 IP、MAC 和型号。集成不会在发现过程
中锁定设备、修改设置或执行 Wi-Fi 配网。

## 先检查旧 App 留下的循环定时

旧 App 写入的循环开关机计划可能保存在设备 MCU 内，所以即使账号无法
登录，机器仍可能每天自动开关。仓库附带经过 Windows、Linux 和 macOS
验证的独立工具：

```bash
cd tools
python3 352air_schedule_manager.py
```

选择设备后会立即显示四个定时槽。建议清除不再需要的设备端计划，再用
Home Assistant 自动化管理开关机时间，避免两套计划互相冲突。详细用法
见[定时管理器说明](docs/schedule-manager.md)。

## HomeKit

Home Assistant 的 `fan` 域本身没有“空气净化器”设备类型，需要在
HomeKit Bridge 中把主风扇指定为 `air_purifier`，并关联 PM2.5 传感器：

```yaml
homekit:
  - filter:
      include_entities:
        - fan.352_air_x83c
    entity_config:
      fan.352_air_x83c:
        type: air_purifier
        linked_pm25_sensor: sensor.352_air_x83c_pm2_5
```

请把示例实体 ID 换成自己 HA 中的实际 ID。这样 Apple“家庭”显示一个
净化器附件，原生提供开关、自动/手动和风量滑块，拉到 0 即关机，并在
附件中关联 PM2.5。HomeKit 的净化器规范没有睡眠/极速模式；本集成把
完整模式保留在 HA 的“运行模式”实体中，同时不把它们变成多个 HomeKit
按钮。

## 隐私与安全

- 不连接 352 云端，不上传遥测。
- 不包含 APK、抓包、证书、完整设备 MAC、内网 IP、HA token 或 Wi-Fi
  信息；自动发现只使用公开的 352 厂商 OUI 前缀。
- 诊断下载会脱敏主机、MAC、鉴权码和原始数据包。
- 自动发现只执行读取，不复刻旧 App 的设备锁定操作。

请只对自己拥有或获准管理的设备使用本项目。
