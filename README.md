# 352 Air Legacy Local

[English](README_EN.md)

为已经联网的 352 设备提供本地 Home Assistant 接入。旧 Air 设备通过
UDP 11530 读取状态和发送控制；新版 Life 设备可通过只读 CoAP 发现并添加
局域网连接状态。无需 352 账号，集成不连接云服务。

> 本项目是社区维护的非官方集成，与 352 厂商没有隶属或背书关系。

## 为什么有这个项目

这不是泛指旧 App“兼容性不好”：APK 把账号登录、token 校验和设备列表
固定指向 `https://352.yunext.com`，设备云入口也使用同一主机名的
`11591` 端口。2026-08-18 通过 Cloudflare 和 Google 的公共 DNS over
HTTPS 复核时，该主机名均返回 `NXDOMAIN`；父域名仍存在，但旧服务主机
记录已经撤下。因此 App 在校验账号密码之前就无法定位服务器，登录必然
失败，并不是净化器损坏或密码输入错误。

X83C 等设备本身仍会在局域网广播状态，也接受独立的 UDP 11530 本地控制。
项目通过 APK 静态分析、脱敏抓包和 X83C 真机验证重新记录了这些本地协议，
并按 Home Assistant 2026.8 接口从零实现。

感谢 [yymonday/ha-352-airpurifier](https://github.com/yymonday/ha-352-airpurifier)
保存了早期 X83/X50 接入经验。当前 v3 是新的 GPL-3.0-or-later 实现，
不继承旧项目源码和 Git 历史。全部公开资料见
[研究资料索引](docs/README.md)：包括[协议分析](docs/protocol-analysis.md)、
[APK 静态分析](docs/apk-static-analysis.md)和
[X83C 脱敏抓包与实机验证](docs/x83c-capture-validation.md)。

## 旧 Air 设备支持程度

| 型号 | 状态读取 | 控制 | 证据与说明 |
|---|---|---|---|
| X83C | 支持 | 支持 | 本项目真机验证；鉴权码从设备学习 |
| X83 | 支持 | 支持 | 原项目实机报告可用；v3 使用同一 A5A0 协议族 |
| X50 | 支持 | 实验性 | 原项目列为实机可用；不同固件的本地控制存在差异 |
| X83C Plus | 实验性 | 实验性 | APK 确认属于 X83 协议族，无对应真机 |
| X50S / X60 / X70 | 实验性 | 实验性 | APK 确认共用 X50 协议族，无对应真机 |
| G30 / G45 | 实验性 | 实验性 | APK 确认长帧、CRC 和控制表，无对应真机 |
| M25 | 实验性 | 仅背光 | M25 是检测仪，不提供净化器电源/模式/风量控制 |

“APK 确认”只表示旧 App 中存在对应构造器和解析器，不保证所有硬件或
固件接受控制。Plus、G30/G45 等零售型号可能存在不同接入体系，应以设备
实际响应为准。

## 新版 Life 设备：本地发现与添加

自动和手动添加都会尝试旧 UDP、CoAP device-info 和 ALCS 发现。
扫描使用 HA 中已启用的 IPv4 网卡，一个机制失败不会阻断其他机制。

内置 35 个产品标识，覆盖 X83C Plus、X86/X86C、X86 Pro、X63C/X66C、
X63C Pet、X88/X88C、X89C、Y100/Y100C、Y109/Y109C、Z70/Z90/Z91/Z120/Z122、
Q80、G30/G45，以及 S100/K10/S130/S106/B420/B425HC、Dr03/Dr10、
Skin/H80/H100/H150/H300/H301/H400/H500/H520 等产品家族。
同一产品标识对应多个型号时会显示合并名称。

**这是身份识别覆盖，不是这些型号均已通过真机或控制验证。**
只有收到有效的本地响应才可添加。Life 条目先显示明确的功能说明，添加后
默认仅创建“局域网连接”诊断实体。X83C Plus 可自愿启用实验性电源开关；
其他 Life 型号不会创建电源、风速、湿度或空气质量实体。连接状态通过只读
探测更新，不表示设备已获控制授权。

### X83C Plus 实验性本地电源控制

**此功能尚未经过 Life 真机验证，很可能不能使用。** 仅 X83C Plus 可选
开启，默认关闭；需要设备所有者合法取得的设备级 `accessKey` 和
`accessToken`。本集成不会自动获取这些凭据，发现响应中的 token 不能代替它们。
设置或重新配置设备时可填写，凭据由 Home Assistant 保存，诊断中会隐藏。

启用后尝试建立 ALCS 安全会话并读取电源状态；读取成功才显示可用的实验性
电源开关。点击后会先读取当前状态、发送一次指令并重新读取确认；如果写入
后超时或确认失败，实际电源状态未知，请到设备上检查。它不提供风速、模式
或其他 Life 型号控制。不同固件可能不支持该接口或授权方式。

本轮不做云登录、设备绑定、蓝牙配网、SoftAP 切网、固件升级或云端劫持。
设备应事先连接到局域网；不回复本地发现的设备不能靠填写型号直接添加。

## 主要功能

- 局域网自动发现和手动 IP/MAC 配置。
- 从设备响应学习 company、协议族和鉴权码，不跨型号写死。
- 单一主风扇实体：0% 关机、风量滑块，以及自动、手动、睡眠、极速和
  型号支持的实验性极净模式；不再创建独立模式实体。
- PM2.5、空气质量、滤芯风量配置、本次开机处理空气量、寿命累计净化
  空气量、当前风量、定时剩余及各型号已确认的环境传感器。离散档位机型
  的当前风量按 APK 中的滤芯配置曲线计算；G30/G45 使用机器上报值。
- 童锁、屏幕、关机定时，以及 G30/G45 的 PTC 控制。
- 被动接收设备广播，并在广播中断时使用只读查询恢复状态。
- 简体中文界面；其他 HA 语言自动使用英语。
- 全部设备通信保持在本地网络。

X83C 的手动模式由风量命令进入。真机对模式命令值 4 和 5 均无响应，
因此本项目不会把“极净”伪装成已支持的 X83C 模式；“极速”是另一个可
持续运行的模式。

## 通过 HACS 安装

当前作为自定义仓库安装：

1. 在 HACS 打开“集成”。
2. 右上角菜单选择“自定义存储库”。
3. 添加：

   ```text
   https://github.com/jack16683/ha-352air-legacy-local
   ```

4. 类别选择“集成”，下载 **352 Air Legacy Local**。
5. 重启 Home Assistant。
6. 进入“设置 → 设备与服务 → 添加集成”，搜索
   **352 Air Legacy Local**。

自动发现会列出有效响应的设备。旧 Air 设备需要确认零售型号；
Life 设备需要确认连接状态及可选实验功能的范围。
扫描失败时可手动填写当前 IP，MAC 可留空，型号可选 Auto 自动识别。
填写旧协议鉴权码或公司码时仍需提供 MAC。发现过程不会锁定设备或执行配网。

仅对支持本地循环定时的旧 Air 设备，配置流程另问是否清除机器内部的
4 组循环定时；默认不清除，只有主动勾选才写入，并在写后连续读取两次确认。
重新配置同一设备时会重新核对身份。

## 先检查旧 App 留下的循环定时

旧 App 写入的循环开关机计划可能保存在设备 MCU 内，所以即使账号无法
登录，机器仍可能每天自动开关。仓库附带经过 Windows、Linux 和 macOS
验证的独立工具：

```bash
cd tools
python3 352air_schedule_manager.py
```

初次添加或重新配置集成时已经可以选择清除四个定时槽。独立工具仍适合
先查询具体内容、设置新的设备端循环计划，或只管理定时而不安装 HA。
建议清除不再需要的设备端计划，再用 Home Assistant 自动化管理开关机
时间，避免两套计划互相冲突。详细用法见
[定时管理器说明](docs/schedule-manager.md)。

## HomeKit

Home Assistant 的 `fan` 域本身没有“空气净化器”设备类型，需要在
HomeKit Bridge 中把主风扇指定为 `air_purifier`，并关联 PM2.5 传感器：

```yaml
homekit:
  - filter:
      include_entities:
        - fan.352_air_x83c
    entity_config:
      fan.352_air_x83c:
        type: air_purifier
        linked_pm25_sensor: sensor.352_air_x83c_pm2_5
```

请把示例实体 ID 换成自己 HA 中的实际 ID。Apple“家庭”会显示一个净化器
附件，提供开关、自动/手动、风量滑块和关联的 PM2.5；拉到 0 即关机。

需要注意：本集成按 HA 的标准把完整运行模式放在主 fan 的
`preset_modes` 中，而 HA 自带 HomeKit Bridge 会把除 `auto` 外的 preset
转换成附属开关。HomeKit 协议本身没有睡眠/极速/极净目标状态。若不希望
看到这些按钮，应在 HA 中建立一个不暴露 presets 的 Template Fan 代理，
HomeKit 只桥接代理，原始 fan 留在 HA 中选择完整模式；不要同时桥接两者。

## 隐私与安全

- 不连接 352 云端，不上传遥测。
- 不包含 APK、原始抓包文件、证书、完整设备 MAC、内网 IP、HA token 或 Wi-Fi
  信息；自动发现只使用公开的 352 厂商 OUI 前缀。
- 诊断下载会脱敏主机、MAC、鉴权码和原始数据包。
- 自动发现只执行读取，不复刻旧 App 的设备锁定操作；配置流程中的定时
  清除是默认关闭、由用户明确选择的独立写入步骤。

请只对自己拥有或获准管理的设备使用本项目。
